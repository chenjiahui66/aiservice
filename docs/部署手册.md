## 0. 动手前必须知道的三件事

### ① 80 和 443 已经被占了

同机的 `www.aindgc.com` 用一个 nginx 容器直绑了宿主机 80/443。

本项目**不去抢**这两个端口。如果给容器做 `80:80` 映射，Docker 会直接报
`port is already allocated`，容器根本起不来。

所以本项目的 `nb-admin` 容器**不映射任何宿主机端口**，只加入网关所在的
docker 网络，由网关按域名反代进来：

```
宿主机 80/443  →  aindgc 的 nginx 容器（网关）
                       ├── www.aindgc.com        → 原来的站点，不动
                       └── community.aindgc.com  → nb-admin:80
                                                      ├── /      → 后台静态页
                                                      └── /api/  → nb-backend:8080
```

### ② 第 6、7 步会重启线上 nginx

网关 nginx 同时承载 `www.aindgc.com`。配置写错会导致它**整个起不来**，
两个站点一起中断。

所以这两步的铁律是：

> **`nginx -t` 通过之后，才允许 `docker restart`。**
> `nginx -t` 不通过就停下来排查，绝不硬来。

### ③ 绝对不要在这台机器上编译 jar

服务器内存实测 1.6G，可用只有 912MB。Maven 编译至少要 1GB 堆，必定 OOM，
而且失败时可能连带拖垮同机已在跑的 aindgc。

本部署用的 `backend/Dockerfile.prebuilt` **没有编译阶段，只 COPY 预构建 jar**，
所以 jar 必须在本地打好（见第 1 步）。

## 3. 查清网关信息（必须在填 .env 之前）

这一步的产出直接决定第 6 步成不成功。**记下三个值**：容器名、网络名、conf.d 挂载路径。

### 3.1 找到占用 80/443 的 nginx 容器

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
```

**找 `0.0.0.0:80->80/tcp` 和 `0.0.0.0:443->443/tcp` 那一行**，
把它的 `.Names` 记下来，下面用 `<GW>` 代表（真实值例如 `aindgc-web`）。

```bash
GW=aindgc-web        # ← 换成你查到的真实容器名
echo $GW
```

### 3.2 查它所在的 docker 网络

```bash
docker inspect $GW --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}{{"\n"}}{{end}}'
```

**预期输出**：一个或多个网络名，例如 `aitools-net`。
记下来，这是 `GATEWAY_NETWORK` 的值。有多个时选主网络。

### 3.3 查它的 nginx 配置挂在哪

```bash
docker inspect $GW --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{"\n"}}{{end}}'
```

**找 `xxx -> /etc/nginx/conf.d` 这一行**，`xxx` 就是第 6 步要放配置的地方。

如果输出里**没有** `/etc/nginx/conf.d`，说明配置是直接打进镜像的，
第 6 步的 `cp` 要改成 `docker cp` 或改用挂载方式（见第 9 节）。

### 3.4 确认现有站点是好的（部署前的基线）

```bash
curl -I https://www.aindgc.com
```

**预期 `HTTP/2 200`。** 记住这个状态——第 6、7 步后要对比。
如果现在就不通，先去修，别让它跟新部署的问题混在一起。

### 3.5 确认内存还够

```bash
free -m
docker stats --no-stream
```

**要求**：available ≥ 700MB。本项目实测常驻约 550~660MB。
不够的话先停掉同机其它服务，硬上必然 OOM。

## 4. 填环境变量

### 4.1 生成 .env

```bash
cd /opt/nbservice
cp deploy/.env.example deploy/.env
```

### 4.2 编辑

```bash
vi deploy/.env
```

**必填 5 项**，其余留空（`deploy.sh` 会自动生成）：

```bash
# ---------- 微信小程序（生产必填，缺了后端拒绝启动）----------
WX_APP_ID=你的AppID
WX_APP_SECRET=你的AppSecret

# ---------- 管理员账号（口令由你决定，不会自动生成）----------
ADMIN_USERNAME=admin
ADMIN_PASSWORD=你的管理口令

# ---------- 网关接入（第 3 步查到的网络名）----------
GATEWAY_NETWORK=aitools-net
```

**留空让脚本生成的**（不要手写）：`MYSQL_ROOT_PASSWORD`、`DB_PASSWORD`、
`JWT_PROVIDER_SECRET`、`JWT_ADMIN_SECRET`。

> ⚠️ 不要为了"省事"给 JWT 密钥手写一个默认值。`application-prod.yml` 用的是
> `${JWT_PROVIDER_SECRET:?}` 启动失败校验，你预先塞个写死的值就等于把这道
> 校验架空了，生产环境会悄悄用上公开可查的签名密钥。

### 4.3 改完确认一下

```bash
grep -E '^(WX_APP_ID|WX_APP_SECRET|ADMIN_PASSWORD|GATEWAY_NETWORK)=' deploy/.env \
  | sed 's/=.*/=<已填>/'
```

**预期**：4 行，都显示 `<已填>`。少一行就回去补。

## 5. 执行部署

```bash
chmod +x deploy/deploy.sh
./deploy/deploy.sh
```

脚本依次做：环境预检（含内存水位）→ 生成 `.env` 里缺的密钥 → 启动容器 →
等后端就绪 → 打印验收命令。

### 5.1 预期输出

```
[INFO] 预检运行环境
[ OK ] docker: Docker version ...
[INFO] 内存总量 1634MB，可用 912MB，Swap 2048MB
[INFO] 本次部署实测常驻约 550~660MB（backend~400 + mysql~210 + nginx~10）
[ OK ] 预检通过

[INFO] 准备环境变量
[INFO] 已生成 MYSQL_ROOT_PASSWORD
[INFO] 已生成 DB_PASSWORD
[INFO] 已生成 JWT_PROVIDER_SECRET
[INFO] 已生成 JWT_ADMIN_SECRET
[ OK ] 管理员账号: admin
[ OK ] deploy/.env 就绪（权限 600）
[ OK ] 微信小程序凭据已配置

[INFO] 启动服务
[ OK ] 容器已启动
[INFO] 等待后端就绪（约 40~90 秒，首次需拉取镜像与初始化数据库）
[ OK ] 后端已就绪
```

### 5.2 卡住不动的排查

**「等待后端就绪」超过 2 分钟还没过**，另开一个终端看日志：

```bash
docker logs --tail 100 nb-backend
```

常见原因：

| 日志里出现 | 原因 | 处理 |
|---|---|---|
| `Access denied for user` | DB 密码对不上 | 删掉 `nb-mysql-data` 卷重建：`docker compose -f deploy/docker-compose.prod.yml down -v` 再重跑 |
| `Required environment variable JWT_PROVIDER_SECRET` | 密钥没生成出来 | 手工补：`echo "JWT_PROVIDER_SECRET=$(openssl rand -hex 16)" >> deploy/.env` |
| `Required environment variable WX_APP_ID` | 微信凭据没填 | 回第 4 步 |
| `Table ... doesn't exist` | schema 没执行 | 首次初始化失败，重建数据卷重来 |
| `Killed` / exit 137 | 内存不足被 OOM killer 杀 | `free -m` 看水位，先腾内存 |

### 5.3 确认容器都健康

```bash
docker compose -f deploy/docker-compose.prod.yml ps
```

**预期**：三个容器 `nb-mysql` / `nb-backend` / `nb-admin` 都在 running，
`nb-mysql` 显示 `healthy`。

### 5.4 容器内部自检（还没接网关，先在内部确认服务是好的）

```bash
docker exec nb-admin wget -qO- http://localhost/v3/api-docs | head -c 200
```

**预期**：一段 OpenAPI JSON。
报连不上就看 `docker logs nb-admin` 和 `docker logs nb-backend`。

## 6. 网关接入（必做）

> 🔴 **这一步会重启承载 `www.aindgc.com` 的 nginx 容器。**
> 下面每一步都先测配置再重启，测不过就停。

### 6.1 先备份网关现有配置

```bash
CONFD=$(docker inspect $GW --format '{{range .Mounts}}{{if eq .Destination "/etc/nginx/conf.d"}}{{.Source}}{{end}}{{end}}')
echo "conf.d 挂载目录: $CONFD"
cp -r "$CONFD" "$CONFD.bak.$(date +%Y%m%d-%H%M%S)"
ls "$CONFD"
```

**预期**：打印出路径，并列出现有配置文件。
这份备份是你的退路——第 6 步出问题就把 `community.conf` 删掉再重启。

### 6.2 装「仅 HTTP」版网关配置

```bash
cp deploy/nginx/community-gateway-http.conf "$CONFD/community.conf"
```

> ⚠️ 这一步装的是 **`-http` 那个文件**，它不含 443 块、不引用任何证书，
> 随时可以装，不会让 nginx 起不来。
> 完整的 `community-gateway.conf` 要等第 7 步证书签好之后再换。

### 6.3 确认 conf.d 里只有一份 community 配置

```bash
docker exec $GW ls /etc/nginx/conf.d/ | grep -i community
```

**预期**：只输出一行 `community.conf`。

> ⚠️ 如果出现两行（比如同时有 `community.conf` 和 `community-old.conf`），
> nginx 会报 `conflicting server name "community.aindgc.com" on 0.0.0.0:80`，
> 容器同样起不来。删掉多余的那个。

### 6.4 测配置（这一步通过了才准重启）

```bash
docker exec $GW nginx -t
```

**预期**：

```
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

**不通过就不要重启。** 把错误贴出来排查，常见的是上一步的冲突或语法。

### 6.5 重启网关

```bash
docker restart $GW
sleep 3
docker ps --filter name=$GW --format '{{.Names}}  {{.Status}}'
```

**预期**：状态是 `Up ... (healthy)` 之类，不是 `Restarting`。

### 6.6 确认旧站点没受影响（每次动网关都要做）

```bash
curl -I https://www.aindgc.com
```

**预期 `HTTP/2 200`**。跟第 3.4 步的基线对比。

**如果不通了**，立刻回滚：

```bash
rm -f "$CONFD/community.conf"
docker exec $GW nginx -t && docker restart $GW
```

### 6.7 容器间连通性自检

```bash
docker exec $GW wget -qO- http://nb-admin/v3/api-docs | head -c 200
```

**预期**：一段 OpenAPI JSON —— 说明网关能按容器名找到 nb-admin。

报 `bad address 'nb-admin'` 说明两者不在同一个 docker 网络：

```bash
# 看 nb-admin 实际在哪些网里
docker inspect nb-admin --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}'
```

如果里面没有你第 3 步查到的网络名，改 `deploy/.env` 的 `GATEWAY_NETWORK`
为正确值，然后重建：

```bash
sed -i 's/^GATEWAY_NETWORK=.*/GATEWAY_NETWORK=正确网络名/' deploy/.env
docker compose -f deploy/docker-compose.prod.yml up -d --force-recreate admin
```

### 6.8 用 HTTP 访问试试

```bash
curl -I -H "Host: community.aindgc.com" http://127.0.0.1/
```

**预期 `HTTP/1.1 200`**（nginx 会给 SPA 返回 index.html）。

> 这一步用 `Host` 头在本机测，**不依赖 DNS**，所以 DNS 还没生效也能验证链路。

## 7. 签发证书

> 前提：`nslookup community.aindgc.com` 已经能返回 `47.98.253.138`。
> 解析不通签不下来，这是硬前提。

### 7.1 确认 DNS 已生效

```bash
nslookup community.aindgc.com
```

**必须**返回 `47.98.253.138`。返回 `Non-existent domain` 就是还没生效，
先去阿里云 DNS 加 A 记录（主机记录 `community`，记录值 `47.98.253.138`）。

### 7.2 从外网验证第 6 步的 HTTP 链路对公网可达

```bash
curl -I http://community.aindgc.com
```

**预期 200**。这一步不通的话，ACME 校验一定失败，先回去查第 6 步。

### 7.3 用 webroot 方式签发

webroot 目录要用第 6 步配置里的 `/var/www/certbot`，
把它换成该目录在**宿主机**上的实际路径：

```bash
WEBROOT=$(docker inspect $GW --format '{{range .Mounts}}{{if eq .Destination "/var/www/certbot"}}{{.Source}}{{end}}{{end}}')
echo "webroot: $WEBROOT"
```

如果输出为空，说明网关没有挂 `/var/www/certbot`，先建一个并加进 `$CONFD`：

```bash
mkdir -p /opt/certbot-webroot
# 在 $CONFD 下新建 acme-webroot.conf，内容见第 9 节
# 然后把 /opt/certbot-webroot 挂进网关容器再重启
```

目录确认没问题后签发：

```bash
certbot certonly --webroot -w "$WEBROOT" \
  -d community.aindgc.com \
  --agree-tos -m 你的邮箱@qq.com --non-interactive
```

**预期**：`Successfully received certificate`。

### 7.4 把证书放到网关能读到的位置

路径要和 `community-gateway.conf` 里的 `ssl_certificate` 一致
（当前是 `/etc/nginx/ssl/community.aindgc.com.pem`）：

```bash
SSLDIR=$(docker inspect $GW --format '{{range .Mounts}}{{if eq .Destination "/etc/nginx/ssl"}}{{.Source}}{{end}}{{end}}')
echo "ssl 目录: $SSLDIR"
```

```bash
cp /etc/letsencrypt/live/community.aindgc.com/fullchain.pem "$SSLDIR/community.aindgc.com.pem"
cp /etc/letsencrypt/live/community.aindgc.com/privkey.pem   "$SSLDIR/community.aindgc.com.key"
```

`SSLDIR` 为空的话，同样需要先建目录并挂进网关容器（见第 9 节）。

### 7.5 确认容器里真的读得到（宿主机有 ≠ 容器里有）

```bash
docker exec $GW ls -l /etc/nginx/ssl/community.aindgc.com.*
```

**预期**：两个文件都在。

> 这是最容易漏的一步：文件拷到宿主机了，但没挂进容器，
> `nginx -t` 就会报 `cannot load certificate`。

### 7.6 换成完整版网关配置（覆盖，不是新增）

```bash
cp deploy/nginx/community-gateway.conf "$CONFD/community.conf"

docker exec $GW ls /etc/nginx/conf.d/ | grep -i community
```

**预期**：仍然只有一行 `community.conf`。
如果出现两行，删掉 http 版那个——同 `server_name` 同端口会冲突。

### 7.7 测配置 → 重启

```bash
docker exec $GW nginx -t
```

**预期**：test is successful。

```bash
docker restart $GW
sleep 3
curl -I https://www.aindgc.com          # 旧站点必须还是好的
```

```bat

set TARO_APP_API_BASE=https://community.aindgc.com

```

微信公众平台后台还要配置 **request 合法域名**：`https://community.aindgc.com`。

## 9. 出问题了怎么办

### 网关起不来了（最严重：两个站点一起断）

```bash
# 1. 看网关日志
docker logs --tail 50 $GW

# 2. 立刻回滚
rm -f "$CONFD/community.conf"
docker exec $GW nginx -t && docker restart $GW
curl -I https://www.aindgc.com      # 确认恢复
```

如果 `community.conf` 删掉还是起不来，把 6.1 步的备份整个还原：

```bash
cp -r "$CONFD.bak.你的时间戳/." "$CONFD/"
docker exec $GW nginx -t && docker restart $GW
```

### 网关配置没挂载目录（第 3.3 步输出里没有 `/etc/nginx/conf.d`）

配置直接打进镜像了。两条路：

**A. 用 `docker cp`（临时，重建镜像后失效）**

```bash
docker cp deploy/nginx/community-gateway-http.conf $GW:/etc/nginx/conf.d/community.conf
docker exec $GW nginx -t && docker restart $GW
```

**B. 重建网关镜像（推荐，一劳永逸）**

在 `$CONFD` 所在目录建 `acme-webroot.conf`（如果需要 ACME webroot）：

```nginx
server {
    listen 80;
    server_name community.aindgc.com;
    location /.well-known/acme-challenge/ { root /var/www/certbot; }
    location / { return 404; }
}
```

⚠️ 前提是网关有挂 `/var/www/certbot`。没有的话，在网关的 compose 文件里加：

```yaml
volumes:
  - /opt/certbot-webroot:/var/www/certbot
  - /opt/nginx-ssl:/etc/nginx/ssl
```

### 后端反复重启

```bash
docker logs --tail 100 nb-backend
docker inspect nb-backend --format '{{.State.OOMKilled}}'
```

`OOMKilled: true` 就是内存不够，`free -m` 看水位，腾内存或调小 `deploy/docker-compose.prod.yml`
里 backend 的 `-Xmx384m`。

### 数据要重来

```bash
cd /opt/nbservice
docker compose -f deploy/docker-compose.prod.yml down -v    # ⚠️ 连数据卷一起删
./deploy/deploy.sh
```

`schema.sql` 会在容器首次初始化时自动执行。

### 端口冲突（不该出现，出现说明配置回退了）

```bash
docker ps --format '{{.Names}} {{.Ports}}' | grep nb-
```

`nb-admin` 应该**没有任何端口映射**。有的话说明用了旧的 compose 文件。

## 10. 日常运维

```bash
cd /opt/nbservice
COMPOSE="docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env"

# 状态 / 日志
$COMPOSE ps
$COMPOSE logs -f backend
docker logs -f nb-backend

# 重启 / 停止
$COMPOSE restart backend
$COMPOSE down            # 保留数据卷
$COMPOSE down -v         # ⚠️ 连数据一起删

# 更新后端：替换 jar 后
cp new/neighborhood-backend.jar backend/target/
$COMPOSE up -d --build backend

# 更新前端：替换 dist 后
rm -rf admin-web/dist && cp -r new/dist admin-web/dist
$COMPOSE restart admin
```

### 证书续期

TLS 在网关上终止，续期后要重启**网关容器**（不是 `nb-admin`）：

```bash
certbot renew --dry-run
cp /etc/letsencrypt/live/community.aindgc.com/fullchain.pem "$SSLDIR/community.aindgc.com.pem"
cp /etc/letsencrypt/live/community.aindgc.com/privkey.pem   "$SSLDIR/community.aindgc.com.key"
docker exec $GW nginx -t && docker restart $GW
```

建议加 crontab 每天试续期。
